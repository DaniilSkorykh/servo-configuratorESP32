# Протокол обмена ПК ↔ ESP32

Версия протокола: **1**
Транспорт: USB Type-C → UART0 ESP32, **115200 8N1**, без аппаратного управления потоком.

## 1. Формат кадра

**JSON Lines**: одно сообщение — одна строка UTF-8, завершённая `\n` (`0x0A`).
Символ `\r` при приёме игнорируется (совместимость с мониторами порта).

```
{"id":1,"cmd":"ping"}\n
{"id":1,"ok":true,"data":{"fw":"1.0.0","proto":1}}\n
```

**Ограничения:**

| Параметр | Значение |
|---|---|
| Максимальная длина строки | 512 байт (включая `\n`) |
| Кодировка | UTF-8, фактически ASCII |
| Вложенность JSON | не более 3 уровней |

Строка длиннее лимита отбрасывается целиком, приёмник синхронизируется по следующему
`\n` и отвечает `E_PARSE` (если удалось извлечь `id`) либо шлёт событие `error`.

### Почему JSON Lines

- **Самосинхронизация.** `\n` — однозначный разделитель кадров; после мусора в линии
  (переподключение USB, перезагрузка ESP32) приёмник восстанавливается на первой же
  границе строки, без поиска сигнатуры и пересчёта CRC.
- **Отладка без инструментов.** Обмен читается в любом мониторе порта; на стенде это
  экономит часы, когда неясно, кто именно не отвечает — плата или сервопривод.
- **Расширяемость.** Новое поле не ломает старого читателя: неизвестные ключи
  игнорируются, а поле `proto` позволяет отследить несовместимость явно.
- **Цена.** Оверхед по трафику. При телеметрии 20 Гц кадр ~140 байт → ~2.8 кБ/с,
  что составляет ≈24 % пропускной способности 115200 бод. Запас достаточный;
  при необходимости частота телеметрии снижается командой `telemetry`.

Целостность отдельно не контролируется: USB CDC уже даёт контроль ошибок на своём
уровне, а битая строка не разбирается как JSON и отбрасывается.

## 2. Типы сообщений

Тип определяется по наличию ключа:

| Ключ | Тип | Направление |
|---|---|---|
| `cmd` | Команда | ПК → ESP32 |
| `ok` | Ответ на команду | ESP32 → ПК |
| `evt` | Асинхронное событие | ESP32 → ПК |

### 2.1. Команда

```json
{"id": 42, "cmd": "move_to", "args": {"pos": 2048}}
```

| Поле | Тип | Обяз. | Описание |
|---|---|---|---|
| `id` | int 1…65535 | да | Идентификатор запроса, назначается ПК, циклический |
| `cmd` | string | да | Имя команды |
| `args` | object | нет | Аргументы; отсутствие эквивалентно `{}` |

### 2.2. Ответ

Успех:

```json
{"id": 42, "ok": true, "data": {}}
```

Ошибка:

```json
{"id": 42, "ok": false, "err": "E_RANGE", "msg": "pos 5000 not in [0, 4095]"}
```

| Поле | Тип | Обяз. | Описание |
|---|---|---|---|
| `id` | int | да | Совпадает с `id` запроса |
| `ok` | bool | да | Результат |
| `data` | object | при `ok:true` | Полезная нагрузка, может быть пустой |
| `err` | string | при `ok:false` | Код ошибки из раздела 5 |
| `msg` | string | нет | Человекочитаемая деталь, для UI и логов |

**Гарантии:** на каждую команду ESP32 отдаёт ровно один ответ с тем же `id`.
Ответы приходят в порядке поступления команд. ПК считает команду потерянной по
таймауту (см. раздел 6) — ответ, пришедший после таймаута, отбрасывается по `id`.

### 2.3. Событие

Событие не имеет `id` и приходит без запроса.

```json
{"evt": "tlm", "data": {}}
```

| `evt` | Когда | Содержимое |
|---|---|---|
| `tlm` | периодически, если телеметрия включена | раздел 4 |
| `state` | при смене состояния устройства | `{"state":"homing","prev":"idle"}` |
| `homing` | результат процедуры Homing | `{"result":"completed","pos":0,"elapsed_ms":3200}` |
| `error` | нештатная ситуация вне контекста команды | `{"err":"E_SERVO_TIMEOUT","msg":"..."}` |
| `boot` | однократно после старта ESP32 | `{"fw":"1.0.0","proto":1,"cfg_loaded":true}` |

Событие `boot` — признак перезагрузки контроллера: ПК обязан перечитать конфигурацию
и сбросить локальное представление о состоянии.

## 3. Команды

### 3.1. Сервисные

#### `ping`

Handshake и автоопределение платы. Отвечает всегда, в любом состоянии.

```
→ {"id":1,"cmd":"ping"}
← {"id":1,"ok":true,"data":{"fw":"1.0.0","proto":1,"dev":"ws-servo-esp32",
                            "servo":"STS3215","servo_id":1,"uptime_ms":15320}}
```

#### `get_config`

Возвращает текущую конфигурацию (раздел 7) из ОЗУ.

```
→ {"id":2,"cmd":"get_config"}
← {"id":2,"ok":true,"data":{"config":{...},"dirty":false}}
```

`dirty` — конфигурация изменена, но ещё не сохранена в NVS.

#### `set_config`

Частичное обновление. Передаются только изменяемые поля; остальные сохраняются.
Валидируется целиком; при ошибке **ни одно поле не применяется** (атомарность).
Применяется к ОЗУ; для сохранения между перезагрузками нужен `save_config`.

```
→ {"id":3,"cmd":"set_config","args":{"config":{"homing":{"speed":400}}}}
← {"id":3,"ok":true,"data":{"config":{...},"dirty":true}}
```

Запрещена в состояниях `homing` и `motor` → `E_STATE`.

#### `save_config`

Записывает текущую конфигурацию в NVS (Preferences).

```
→ {"id":4,"cmd":"save_config"}
← {"id":4,"ok":true,"data":{"dirty":false}}
```

#### `restore_defaults`

Загружает заводские значения в ОЗУ. Аргумент `save` (bool, по умолчанию `false`)
дополнительно записывает их в NVS.

```
→ {"id":5,"cmd":"restore_defaults","args":{"save":true}}
← {"id":5,"ok":true,"data":{"config":{...},"dirty":false}}
```

#### `telemetry`

Управление потоком событий `tlm`.

```
→ {"id":6,"cmd":"telemetry","args":{"enabled":true,"period_ms":50}}
← {"id":6,"ok":true,"data":{"enabled":true,"period_ms":50}}
```

`period_ms`: 20…1000, по умолчанию 50 (20 Гц).

### 3.2. Управление движением

#### `home_start`

Запускает процедуру Homing с параметрами из конфигурации. Возвращает управление
немедленно; результат приходит событием `homing`.

```
→ {"id":7,"cmd":"home_start"}
← {"id":7,"ok":true,"data":{"state":"homing"}}
  …
← {"evt":"homing","data":{"result":"completed","pos":0,"elapsed_ms":3200}}
```

`result`: `completed` | `timeout` | `aborted` | `error`.
Допустима только из `idle`; иначе `E_STATE`.

#### `home_abort`

Прерывает Homing, останавливает привод, состояние → `idle`,
событие `homing` с `result: "aborted"`.

#### `move_to`

Позиционный режим. Требует успешно выполненного Homing, иначе `E_NOT_HOMED`.

```
→ {"id":8,"cmd":"move_to","args":{"pos":2048,"speed":800}}
← {"id":8,"ok":true,"data":{"target":2048}}
```

| Аргумент | Тип | Обяз. | Описание |
|---|---|---|---|
| `pos` | int | да | Целевая позиция, шаги; должна лежать в `[pos_min, pos_max]`, иначе `E_RANGE` |
| `speed` | int | нет | Скорость перемещения; по умолчанию `operating.speed` |

Ответ подтверждает **приём** команды, а не завершение движения. Факт достижения
позиции ПК определяет по телеметрии (`moving: false`).

#### `motor_run`

Непрерывное вращение (wheel mode). Программные границы позиции в этом режиме
не действуют — оператор отвечает за остановку.

```
→ {"id":9,"cmd":"motor_run","args":{"dir":"cw","speed":600}}
← {"id":9,"ok":true,"data":{"dir":"cw","speed":600}}
```

| Аргумент | Тип | Обяз. | Описание |
|---|---|---|---|
| `dir` | `cw` / `ccw` | да | Направление |
| `speed` | int | нет | По умолчанию `operating.speed` |

#### `stop`

Немедленная остановка любого движения. **Разрешена в любом состоянии**, включая
`fault`, и обрабатывается вне очереди. Состояние → `idle`.

```
→ {"id":10,"cmd":"stop","args":{"emergency":true}}
← {"id":10,"ok":true,"data":{"state":"idle"}}
```

`emergency` (bool, по умолчанию `false`) — дополнительно снимает момент с привода
(torque off). Обычный `stop` момент удерживает.

## 4. Телеметрия

```json
{"evt":"tlm","data":{
  "seq": 1042, "ts": 152300,
  "pos": 2048, "spd": 0, "load": 120,
  "volt": 74, "temp": 31, "cur": 45,
  "moving": false, "state": "idle", "homed": true, "err": null}}
```

| Поле | Тип | Единица | Описание |
|---|---|---|---|
| `seq` | int | — | Счётчик кадров, циклический 0…65535. Разрыв = потеря кадров |
| `ts` | int | мс | `millis()` ESP32 с момента старта |
| `pos` | int | шаг | Текущая позиция, 0…4095 (1 шаг ≈ 0.088°) |
| `spd` | int | шаг/с | Текущая скорость, знак = направление |
| `load` | int | 0.1 % | Нагрузка, 0…1000; знак = направление приложения |
| `volt` | int | 0.1 В | Напряжение питания (74 = 7.4 В) |
| `temp` | int | °C | Температура |
| `cur` | int | 6.5 мА | Ток (по документации Feetech) |
| `moving` | bool | — | Флаг движения от сервопривода |
| `state` | string | — | Состояние устройства, раздел 8 |
| `homed` | bool | — | Homing выполнен успешно с момента старта |
| `err` | string / null | — | Код активной ошибки либо `null` |

Поля `volt`, `temp`, `cur` могут отсутствовать, если сервопривод их не вернул —
приёмник обязан это допускать и не падать.

**Единицы измерения** приведены по документации Feetech на ST-серию.
Масштаб `spd`, `load` и `cur` подлежит проверке на реальном стенде: у разных
ревизий STS3215 встречаются расхождения. Приложение отображает сырые значения
регистров, поэтому уточнение масштаба не затрагивает логику обмена.

## 5. Коды ошибок

| Код | Значение | Типичная причина |
|---|---|---|
| `E_PARSE` | Строка не разобрана как JSON | помехи в линии, обрыв кадра |
| `E_SCHEMA` | Нарушена структура сообщения | нет `cmd`, `args` не объект |
| `E_UNKNOWN_CMD` | Неизвестная команда | несовпадение версий ПО |
| `E_RANGE` | Значение вне допустимого диапазона | целевая позиция за границами |
| `E_STATE` | Команда недопустима в текущем состоянии | `set_config` во время Homing |
| `E_NOT_HOMED` | Требуется выполненный Homing | `move_to` до калибровки |
| `E_SERVO_TIMEOUT` | Сервопривод не ответил | обрыв шины, нет питания привода |
| `E_SERVO_ERROR` | Сервопривод вернул флаг ошибки | перегрев, перегрузка, overload |
| `E_TIMEOUT` | Превышено время операции | timeout Homing |
| `E_NVS` | Ошибка энергонезависимой памяти | нет места, сбой записи |
| `E_INTERNAL` | Внутренняя ошибка прошивки | непредвиденное состояние |

Ошибки на стороне ПК (порт занят, USB отключён, нет ответа ESP32) в линию не
попадают и определены в приложении: `E_PORT`, `E_LINK_TIMEOUT`, `E_DISCONNECTED`.

## 6. Таймауты и надёжность

| Параметр | Значение | Сторона |
|---|---|---|
| Таймаут ответа на команду | 1000 мс | ПК |
| Таймаут `save_config` / `restore_defaults` | 3000 мс | ПК |
| Число повторов команды | 2 (только идемпотентные) | ПК |
| Потеря связи по молчанию телеметрии | 3 периода, минимум 500 мс | ПК |
| Watchdog связи | `safety.link_timeout_ms`, 0 = выключен | ESP32 |

**Повторы.** Автоматически повторяются только идемпотентные команды: `ping`,
`get_config`, `telemetry`. Команды движения (`move_to`, `motor_run`, `home_start`)
не повторяются — потерянный ответ на движение безопаснее показать как ошибку, чем
рискнуть повторным пуском привода.

**Watchdog связи.** Если ESP32 находится в `motor` или `position` и не получал ни
одного сообщения от ПК дольше `link_timeout_ms`, он самостоятельно выполняет `stop`
и переходит в `fault` с `E_LINK_TIMEOUT`. Это защищает от ситуации, когда USB
выдернут во время непрерывного вращения. ПК поддерживает канал живым, периодически
отправляя `ping` в паузах между командами.

## 7. Конфигурация

Хранится в NVS (Preferences) ESP32, переживает перезагрузку по питанию.

```json
{
  "version": 1,
  "servo": {"id": 1},
  "homing": {
    "dir": "ccw",
    "speed": 300,
    "load_threshold": 450,
    "timeout_ms": 10000,
    "max_travel": 4096,
    "zero_position": 0
  },
  "operating": {
    "speed": 1000,
    "load_limit": 600,
    "pos_min": 0,
    "pos_max": 4095,
    "accel": 50
  },
  "safety": {"link_timeout_ms": 1000}
}
```

| Параметр | Тип | Диапазон | По умолч. | Описание |
|---|---|---|---|---|
| `servo.id` | int | 0…253 | 1 | Адрес привода на шине |
| `homing.dir` | enum | `cw` / `ccw` | `ccw` | Направление поиска упора |
| `homing.speed` | int | 1…3000 | 300 | Скорость поиска, шаг/с |
| `homing.load_threshold` | int | 50…1000 | 450 | Порог нагрузки (0.1 %), по которому фиксируется упор |
| `homing.timeout_ms` | int | 1000…60000 | 10000 | Предельное время процедуры |
| `homing.max_travel` | int | 100…8192 | 4096 | Предельный путь поиска, шаг |
| `homing.zero_position` | int | 0…4095 | 0 | Позиция, назначаемая упору после успеха |
| `operating.speed` | int | 1…3000 | 1000 | Рабочая скорость, шаг/с |
| `operating.load_limit` | int | 50…1000 | 600 | Ограничение нагрузки (0.1 %) |
| `operating.pos_min` | int | 0…4095 | 0 | Нижняя граница рабочего диапазона |
| `operating.pos_max` | int | 0…4095 | 4095 | Верхняя граница рабочего диапазона |
| `operating.accel` | int | 0…255 | 50 | Ускорение; 0 — без ограничения |
| `safety.link_timeout_ms` | int | 0…10000 | 1000 | Watchdog связи; 0 отключает |

**Межполевые ограничения** (проверяются вместе с диапазонами):

- `operating.pos_min < operating.pos_max`;
- `homing.zero_position` ∈ `[operating.pos_min, operating.pos_max]`;
- `homing.load_threshold ≤ operating.load_limit`.

Поле `version` фиксирует схему конфигурации. При чтении из NVS конфигурации с
другой `version` прошивка загружает значения по умолчанию и сообщает об этом в
событии `boot` полем `cfg_loaded: false`.

## 8. Состояния устройства

```
                  ┌──────────────────────────────┐
                  ▼                              │
  boot ──────► idle ──── home_start ────► homing ┤
                │ ▲                              │
      move_to   │ │  цель достигнута / stop      │
                ▼ │                              │
            position ─────────────────────────── ┤
                │ ▲                              │
     motor_run  │ │  stop                        │
                ▼ │                              │
              motor ──────────────────────────── ┤
                                                 │
                          ошибка ────────► fault ┘
                                            │
                                          stop
                                            ▼
                                          idle
```

| Состояние | Описание | Допустимые команды |
|---|---|---|
| `idle` | Готов, движения нет | все |
| `homing` | Выполняется поиск упора | `stop`, `home_abort`, `ping`, `get_config`, `telemetry` |
| `position` | Отработка целевой позиции | все, кроме `home_start` |
| `motor` | Непрерывное вращение | `stop`, `motor_run`, `ping`, `get_config`, `telemetry` |
| `fault` | Зафиксирована ошибка, движение запрещено | `stop`, `ping`, `get_config`, `set_config`, `telemetry` |

Выход из `fault` — только через `stop`, который снимает ошибку и переводит в `idle`.
Это осознанно требует явного действия оператора: ошибка не должна пропадать сама,
пока причина не осмыслена.

Состояния `disconnected` в протоколе нет — это состояние приложения, не устройства.

← {"id":4,"ok":true,"data":{"config":{...},"dirty":true}}

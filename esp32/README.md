# Прошивка ESP32

Прошивка для платы **Waveshare Servo Driver with ESP32** (SKU 21593), управляющая
сервоприводом **Feetech STS3215** и обменивающаяся с настольным приложением по
протоколу из [`../docs/PROTOCOL.md`](../docs/PROTOCOL.md).

ESP32 выступает нижним уровнем: принимает от ПК высокоуровневые команды
(`home_start`, `move_to`, `motor_run`, `stop`), а работу с приводом по шине
выполняет самостоятельно — предпочтительный вариант из п. 6.1 задания.

## Сборка и прошивка

Требуется [PlatformIO Core](https://platformio.org/install/cli).

```bash
cd esp32
pio run                # сборка
pio run -t upload      # прошивка платы
pio device monitor -b 115200   # просмотр обмена
```

Плата определяется автоматически; при нескольких портах нужный указывается явно:
`pio run -t upload --upload-port COM3`.

> **Windows и кириллица в пути.** Компилятор xtensa не работает с путями,
> содержащими не-ASCII символы. Если имя пользователя записано кириллицей,
> сборка падает с `Arduino.h: No such file or directory`, хотя файл на месте.
> Решается переносом каталога PlatformIO:
> `set PLATFORMIO_CORE_DIR=C:\pio` (или `PLATFORMIO_CORE_DIR=C:/pio pio run`).

## Подключение оборудования

| Соединение | Назначение |
| --- | --- |
| ПК → плата, USB Type-C | питание логики, обмен с приложением (115200 бод) |
| Плата → привод, 3-контактный шлейф | шина TTL, 1 000 000 бод, GPIO 18 (RX) и GPIO 19 (TX) |
| Внешнее питание 6–12 В | питание привода; для STS3215 обычно 7.4 В |

Питания от USB для привода недостаточно: без внешнего источника он не
запустится, а плата будет уходить в перезагрузку под нагрузкой. Номинал
источника выбирается по напряжению конкретного экземпляра привода.

Распиновка и параметры шины собраны в [`include/board_config.h`](include/board_config.h) —
при переходе на другую ревизию платы правится только этот файл.

## Устройство прошивки

| Файл | Назначение |
| --- | --- |
| `src/main.cpp` | приём строк от ПК, главный цикл |
| `src/controller.cpp` | конечный автомат, команды, Homing, телеметрия, защиты |
| `src/settings.cpp` | проверка конфигурации и хранение в NVS |
| `src/servo_bus.cpp` | протокол шины Feetech ST-серии |

### Неблокирующий цикл

Ни одна операция не останавливает главный цикл. Homing не «ждёт» упора в цикле,
а продвигается по шагам в `tick()`, ожидание достижения позиции устроено так же.
Иначе команда `stop`, поданная во время Homing, не была бы принята — а именно
она обязана исполняться в любом состоянии.

### Драйвер шины

Протокол Feetech реализован самостоятельно, а не взят из библиотеки SCServo:
прошивке нужен небольшой набор операций, а таблица регистров и порядок байтов
собраны в одном месте и правятся точечно.

**Различие SC- и ST-серий.** У ST-серии, к которой относится STS3215,
многобайтовые значения передаются младшим байтом вперёд; у SC-серии — старшим.
Реализован ST-вариант; место, где это учитывается, — `toWord` и `fromWord`
в [`include/servo_bus.h`](include/servo_bus.h). Задание отдельно предупреждает об
этом расхождении, и оно же — первое, что стоит проверить, если привод отвечает,
но значения выглядят бессмысленными.

Блок обратной связи (позиция, скорость, нагрузка, напряжение, температура, ток,
признак движения) читается одним запросом: последовательные чтения по регистру
заняли бы на порядок больше времени и сбили период телеметрии.

### Калибровка нуля

После успешного Homing упору назначается координата `homing.zero_position`.
Смещение хранится в прошивке (`positionOffset_`), а регистр `OFS` привода
не изменяется. Причины:

* запись в EEPROM привода расходует её ресурс при каждой калибровке;
* изменённое смещение осталось бы в приводе и после отключения контроллера,
  меняя его поведение с любым другим ПО.

Следствие: после перезагрузки контроллера `homed` сбрасывается и Homing нужно
выполнить заново. Это осознанный выбор — считать положение известным без
подтверждения небезопасно.

### Меры безопасности

| Механизм | Что делает |
| --- | --- |
| Watchdog связи | останавливает привод, если ПК молчит дольше `safety.link_timeout_ms` |
| Контроль нагрузки | останавливает при превышении `operating.load_limit` дольше 300 мс |
| Пауза после старта Homing | 300 мс, чтобы бросок момента при трогании не был принят за упор |
| Ограничения Homing | таймаут и предельный путь; при нарушении — остановка и `fault` |
| Контроль ответов привода | пять подряд неудачных опросов переводят в `fault` |
| Границы позиции | цель вне `[pos_min, pos_max]` отвергается с `E_RANGE` |
| Выход из `fault` | только явной командой `stop` |

Watchdog связи работает в паре с фоновым `ping` приложения: без него он
срабатывал бы на любой штатной паузе, а без watchdog привод продолжал бы
вращаться после выдёргивания USB.

## Конфигурация

Хранится в NVS (`Preferences`, пространство имён `servocfg`) и переживает
перезагрузку по питанию. При несовпадении версии схемы или непрохождении
проверки устройство поднимается на значениях по умолчанию и сообщает об этом
в событии `boot` полем `cfg_loaded: false` — отказываться от старта из-за
испорченной конфигурации нельзя.

Диапазоны и значения по умолчанию совпадают с
`desktop_app/servo_configurator/protocol/schema.py`; совпадение проверяется
тестом `tests/test_firmware_contract.py`.

## Что проверено, а что нет

Прошивка **собирается** (`pio run`, RAM 6.8 %, Flash 23.3 %, без предупреждений
при `-Wall -Wextra`) и проверена на согласованность с протоколом. На физическом
оборудовании она **не запускалась** — у автора нет платы и привода.

Логика конечного автомата, Homing и защит перенесена из
`desktop_app/servo_configurator/simulation/firmware.py`, покрытой тестами,
поэтому поведение воспроизведено, а не написано заново.

При первом включении на стенде стоит проверить в первую очередь:

1. **Порядок байтов и адреса регистров** — если позиция читается как мусор,
   расхождение здесь;
2. **Знак направления**: `cw` считается убыванием счётчика позиции, что зависит
   от монтажа привода;
3. **Масштаб скорости, нагрузки и тока** — приведён по документации Feetech,
   у ревизий встречаются расхождения;
4. **Порог `homing.load_threshold`** — подобран по модели и почти наверняка
   потребует калибровки под реальную механику;
5. **Скорость шины**: заводское значение STS3215 — 1 000 000 бод; если привод
   не отвечает, стоит проверить его настройку.

Обмен полностью читаем в мониторе порта, поэтому первичная диагностика на
стенде не требует дополнительных инструментов.

## Заимствования

Собственный код. Использованы открытые сведения официальной документации
Waveshare (распиновка, скорости) и Feetech (таблица регистров ST-серии).
Библиотека SCServo не включена; ArduinoJson подключается как зависимость
PlatformIO, её лицензия — в [`../LICENSES/`](../LICENSES/).
